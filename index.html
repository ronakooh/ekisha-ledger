Myntra Customers
Approximate repeat-customer tracking — see caveat below

Approximate, not exact: Myntra masks real customer contact info entirely — no usable email or phone is ever provided to sellers on this channel. This uses the customer's name + address + pincode as the best available identity proxy (the courier needs a real address, so that part isn't masked). Cross-checked against the Shopify/website channel's independently-verified repeat rate and landed close, which is reassuring, but minor address text differences for the same real person will undercount, and two different people sharing a name and pincode would overcount. Accumulates permanently from every Sale Orders file uploaded (historical + daily), deduplicated by line item so overlapping uploads never double-count.

Settings & Sync
Data source and security status
Data source

"Pull latest backup" parses every backup file sitting in the Drive folder — not just the newest — and merges them by company (matched on GSTIN, so multiple years of the same company combine into one continuous history). It also recognizes every marketplace reconciliation file (Unicommerce/Shipway/Fastrr/Myntra/Amazon) and every HDFC bank statement PDF in the same folder, matching bank credits to each channel's settlement by reference number for the Reconciliation tabs. New or changed files are downloaded and parsed fresh each sync; unchanged files are skipped and reused from the last sync that saw them, so adding more files over time doesn't make sync slower.
